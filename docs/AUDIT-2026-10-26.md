# Moo audit — 26 October 2026

This is the initial audit record. R1–R11 were subsequently approved and implemented; see [the refactor record](REFACTOR-PROGRESS.md) for current checks and remaining target-browser verification. The findings and lint counts below describe the first pass.

This audit applies repairs to the existing product and separates larger changes for approval. The main risks were shared event cleanup, background and image storage lifecycles, stale widget state, date handling, and inherited Mue infrastructure. The dashboard's visual direction is retained. Discord components, notifications, experimental controls, dormant quote/Marketplace material and reusable layout exports remain available.

## Coverage and evidence

The repository-wide inventory covers **380 source, style and data files**, including **258 JavaScript modules**, under `src`, `scripts`, `manifest` and `safari`. All executable modules were parsed and their static and literal dynamic imports were scanned; no unresolved imports were found. Feature implementations, their callers, storage and request paths, shared controls, styles, package/build configuration and release workflows received source review. Translation data was inventoried; prose editing covers UK/US English and English strings inside components, not a review of every translated sentence.

Browser checks used the local Vite app in Codex's browser at a 1280 × 720 viewport and the narrow viewport later present beside the chat. These checks cover visible composition and selected interactions. They do not establish behavior inside an installed Firefox or Zen extension. Google OAuth, account mutations, live-stream recovery, real storage exhaustion, exhaustive keyboard use, screen readers, contrast across arbitrary wallpapers and long-running memory/CPU profiles remain untested in the target browsers. No account was connected and no issue or release was submitted.

Evidence is saved in [verification.json](audit/2026-10-26/verification.json), the [source inventory](audit/2026-10-26/source-inventory.json), [JavaScript findings](audit/2026-10-26/javascript-findings.json) and [stylesheet findings](audit/2026-10-26/stylesheet-findings.json). These are observations from this checkout, not a release certification.

## UI and wording

The existing dark/glass system remains the product's visual basis. The direct fixes improve controls and fit; they do not resolve every UI issue.

- Switches use native checkbox behavior with switch semantics. Their accessible names come from the setting row, so five controls no longer all announce themselves as “Enabled”. Space was tested on Scratch notes and the original off state was restored.
- Dropdowns keep focus on the control, expose the active option and support arrows, Home, End, Enter, Space, Escape and Tab. Digital → Analogue → Digital was verified with keyboard selection.
- Reset actions and the main modal close control are actual buttons. Text fields have associated labels; row labels also name otherwise unnamed sliders and dropdowns. Tooltips have stable IDs, tooltip roles and timer cleanup.
- Settings dialogs hide the dashboard from screen readers while open. The main settings and setup dialogs have names. Nested-dialog naming and behavior still need the broader accessibility pass below.
- Navigation rows can be reached by keyboard. A background row's dropdown no longer also triggers navigation to the Source page.
- Fixed control widths shrink to their container, settings rows can wrap, and side-rail children are constrained to the viewport. The narrow sidebar/rail layout still requires a structural change.
- Reduced-motion preferences suppress decorative CSS motion. Slider animation cleanup is improved, but JavaScript-driven motion needs a complete follow-up policy.
- **Search/Ask Bar remains borderless while focused and typing**, as requested during this audit. Its existing soft underline remains the focus treatment; the general signature-colour outline is overridden only for this input.

The Humanizer pass used Apostol's operational profile. It changed **96 English hint/description entries** across `en_GB` and `en_US`, plus the error-form text and English hints inside Google and RSS settings. It favours the action or outcome over implementation language: “Which calendars feed the calendar widget” becomes “Choose which calendars appear on your page.” The image-storage hint no longer claims a fixed localStorage limit for IndexedDB images, and backup wording makes the omitted uploaded images and Google sign-in explicit. Existing usable copy and other locales were retained.

## Further development

### Local quote packs

Local packs fit Moo's offline-first direction and can reuse the existing widget registry, placement controls and card surfaces without reintroducing Marketplace.

A first version should offer one Quotes widget with a bundled pack, an import action for JSON packs, pack selection, Next, copy, favourite and a choice between “daily” and “each new tab”. Keep the quote and attribution selectable. Daily selection should be consistent across tabs; random selection should avoid immediate repeats. Manual Next should not silently change the configured rotation mode.

A pack needs a schema version, stable pack/quote IDs, title, language, pack source/licence, quote text, author and an optional work/source citation. Keep quotes as text, reject malformed or oversized imports, validate URLs and show an import preview with duplicate detection. Store local packs in IndexedDB, include them in the future backup format, and retain attribution when copying. A pack author should be able to distinguish a verified quotation from an attributed or translated one. Bundled material needs a source/licence review before shipping.

The first UI can stay small: pack list, import/remove, rotation and attribution visibility. Author/tag filters, favourite-only rotation, custom edits and multiple quote widgets can follow if they prove useful. Existing quote translation keys and styles are starting material, not a requirement to restore the old implementation.

## Validation and limits

- `bun run test`: **19/19 pass** in both `Europe/Kyiv` and `America/Los_Angeles`. Tests cover event cleanup and recursion, repeated subscriptions, first-run migration, malformed imports, date-only/all-day conversion, natural-date parsing, URL schemes, offline RSS, token-refresh coalescing, committed IndexedDB writes, metadata preservation, migration/deletion, connection closure, video detection, feed deduplication and weather cache identity.
- `bun run build`: **passes**. The Firefox ZIP's manifest version and referenced new-tab, icon and background-script files were verified.
- Dependency installation was checked against the frozen lockfile. A forced reinstall repaired the local stale transitive Stylelint installation; no node_modules patch is part of the change.
- Changed source/data files were formatted. The import scan reports **no unresolved imports**.
- ESLint: **18 errors, 14 warnings**. Stylelint: **369 findings**. The original combined lint command still fails; this report does not present it as a passing check.
- Browser evidence confirms the existing desktop composition, clock dropdown keyboard selection, uniquely named native switches, named settings dialog/close button and the requested borderless Search/Ask Bar focus. Narrow layout problems are recorded above rather than marked solved.

No aggregate health score is assigned: target-browser runtime profiling, full contrast/accessibility checks and the complete responsive matrix have not been performed. The next approval should select the refactor scopes above, with their acceptance criteria, rather than approve a public release of this checkout.
