# Data and connections

Moo stores preferences, notes, links and local activity counters in your browser. Uploaded backgrounds and pasted images are kept in IndexedDB. Google tokens use extension storage; OAuth client details and optional media-provider keys use local settings. Backups omit sign-in and private keys. Include pictures when exporting if you want to keep them in the backup. Imported files are validated before application. Your browser profile and exported backups can contain private notes and images, so store copies accordingly.

The local counters are not sent to an analytics service. The inherited Sentry error-reporting connection has been removed. Report buttons open Moo's GitHub issue form; review what you include before submitting. This document describes the checked-in code, not the retention policies of outside services.

| Feature | Destination and data |
| --- | --- |
| Weather | `api.muetab.com/v2/weather` receives the configured city. If you use automatic location, the browser first asks for location access and the GPS lookup sends coordinates to `api.muetab.com/v2/gps`. Expanded forecasts also use Open-Meteo geocoding and forecast endpoints. |
| Habits | Titles, schedules, counts and dated history stay in local settings. They are included in settings backups. No account or remote habit service is used. |
| Air Quality | Open-Meteo geocoding receives a city search or the saved Weather city. Its Air Quality API receives the selected coordinates and model options. The widget does not request device location permission. The latest matching forecast is cached locally and excluded from backups. |
| Bookmarks | With optional permission, Moo reads this browser profile’s web bookmarks locally; snapshots stay in memory and native bookmark URLs are not sent to the connected services. Raindrop receives collection/search filters; Readwise receives Reader location, type or tag filters and Daily Review requests. Each receives its own token in an authorization header. The widget only reads libraries. Tokens stay in local settings; remote indexes, collection names and discovery/open history use IndexedDB, with a localStorage cache for immediate open counts. Both are excluded from backups. Changing credentials isolates the cache; profile reset/restore clears it. Covers and images in notes contact their referenced hosts with no referrer. |
| GitHub | `api.github.com` receives the configured username, repository and search filters, plus the optional token in an authorization header. The widget only reads data. Tokens and cached results, which may include private repository titles, full issue/PR descriptions and developer metadata, stay in local settings and are excluded from backups. Clearing the token removes the cached results. Opening a body preview adds no API request; images and media in a description load from their referenced hosts. |
| Library backgrounds | Mue's image API receives source/filter/quality choices. Images load from the returned provider/CDN address. Explicit view/download/heart actions may update the image's counter through that API. |
| Video and live backgrounds | Coverr, Mixkit, Pixabay, Pexels or the selected broadcaster/CDN receives normal media requests, including your IP address. Provider search choices and optional keys are sent to that provider. Live streams stop loading while the tab is hidden. |
| Google widgets | After you connect, Google receives OAuth requests and the selected mail searches, calendar/task reads and edits. The OAuth client secret is sent to Google's token endpoint; it is not a confidential secret in a Desktop app client. Disconnect removes the local token and attempts remote revocation. |
| Calendar event maps | Only choosing Show map sends the event location to Photon (`photon.komoot.io`) for address lookup. Coordinates and chosen map bounds load an OpenStreetMap embed; Google credentials, event titles and guest lists are not sent to either map service. Coordinates already present in the location skip address lookup. Matching places are cached briefly in memory per connected account and are not included in backups. Description markup is rendered without remote images or embedded resources. |
| RSS | Selected feed and article websites receive requests. Full-article mode can fetch stories before you open the reader; turn it off to use feed summaries only. Embedded article pictures contact their hosts when displayed. With a Feedly account, requests go to `cloud.feedly.com` and the developer token stays in local settings; a story is marked read there only when you open it, and an import or export stays in this profile. |
| Quick links | Custom images load from their supplied addresses. Automatic title/icon lookup contacts the selected site or configured icon service. |
| Search/Ask Bar | Submitting opens the selected service with your query in its URL. It is then handled by that service. Typing alone does not submit the query. |
| Fonts and photo maps | A custom Google Font contacts Google's font service. Displaying the photo map contacts the configured map provider. |
| Support and translations | These actions open Moo's GitHub repository or local documentation links; issue text is submitted only when you submit the GitHub form. |

Offline mode stops application API entry points. Already displayed external images, custom CSS URLs and browser-managed media can have their own resource lifecycles; offline mode is not a network firewall.

The manifest requests `storage` for saved data, `identity` for Google sign-in and `clipboardWrite` for explicit copy actions. Google, GitHub, Open-Meteo and Photon API hosts are declared for their widgets. Optional HTTP(S) host access allows user-selected feed, Feedly and media sites; requesting access can show a browser prompt, and granted hosts can be reviewed in the add-on's permissions. See [Mozilla's host-permission documentation](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/host_permissions).

Restore settings keeps personal data and sign-in. Erase all local data removes local preferences, notes, links, uploaded pictures and stored Google sign-in; it does not delete account data at Google, revoke every previously granted host permission or remove backups outside the browser.
